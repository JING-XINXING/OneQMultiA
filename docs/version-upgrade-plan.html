02

当前版本（v0.2.0）功能矩阵与架构亮点

核心结论：v0.2.0 相比早期 MVP 规划已大幅超前完成了「LLM 多厂商最优解重写」「无密码账号绑定与网址防篡改校验」以及「Windows/macOS 桌面安装包流水线」三大高价值特性，具备清晰的模块化边界。

后端与自动化核心亮点 Backend & CDP

  • CDP 免密登录态复用：通过 connect_over_cdp 接入独立 Profile 的 Chrome，规避复杂的登录态加密保存与反爬风控，内置 30s 自动重连协程。
  • SPA 强容错通用适配器：GenericAdapter 支持键盘合成事件注入、自动点击关闭遮罩弹窗、配置选择器失效时降级 7 类输入选择器与 9 类响应容器选择器。
  • 原地更新与思考态识别：page_nav.py 兼容豆包/Pi 等原地改写末尾节点的 DOM 模式，_looks_incomplete() 过滤“思考中/Thinking”防截断。
  • 双引擎最优解合成：无 Key 时采用中文 2-gram Jaccard 相似度评分与要点聚类；配 Key 时支持 DeepSeek、Kimi、千问、GLM、MiniMax、豆包等 9 家网关精编并持久化缓存至 qa_pairs.optimal_answer。

前端交互与工程交付能力 Frontend & Packaging

  • 实时流式三视图切换：React 端支持「最优答案 / 各平台回答 / 对比分析（速度、篇幅、相似度、文本 Diff）」无损切换，支持全局停止或单平台独立终止。
  • 五格式会话导出：支持 MD / TXT / HTML / PDF / DOCX 导出，妥善处理 RFC 5987 中文附件名编码并自动附带最优答案。
  • 生产同源挂载与跨平台打包：webui.py 在存在 frontend/dist 时由 FastAPI 单端口同时承载 UI 与 API；配合 PyInstaller 与 GitHub Actions 自动产出 macOS .dmg 与 Windows setup.exe。
03

现存问题与技术短板深度诊断

结合源码逐行审查，将发现的 14 项核心问题 按影响半径与紧急程度划分为 P0（功能失效/并发破坏/数据安全）、P1（质量损耗/性能阻塞）与 P2（体验缺口/工程门禁）三级：

级别 问题模块与现象 代码定位 根因剖析与业务影响
P0-1 专用适配器钩子为死代码，定制逻辑未生效 platforms/specialized/*.py
platforms/generic.py		 ChatGPTAdapter、DeepSeekAdapter、KimiAdapter 均重写了 send_question() 并调用 super().send_question()，但父类仅实现了 ask()，根本不存在 send_question，子类代码在运行时被完全绕过。
P0-2 共享 BrowserContext 并发切前台导致焦点抢占与同域竞态 core/dispatcher.py
(_get_or_open_page)		 最多 5 个并发协程同时对各自 Tab 调用 page.bring_to_front() 后模拟键盘打字，焦点频繁跳变极易造成漏字或输入串台；同域名多平台或并发请求还会共用同一 Page 实例。
P0-3 首字响应时间（TTFT）埋点位置错误 platforms/generic.py
(L351–356)		 timing.first_token_at 在填完输入框后、点击发送按钮之前即被赋值，记录的是本地填表时刻而非模型首字返回时刻，导致 TTFT 指标失真。
P0-4 数据库结构迁移与全量配置覆盖缺乏自动备份与事务保护 platform_manager/importer.py
storage/migrate.py		 import_json_replace() 先清空全表并 commit()，再逐条创建；若中途某条 JSON 异常将导致原有 23 个平台配置全部丢失；migrate_schema() 改表前亦无自动数据库备份。
P0-5 分享链接缺前端页面，局域网/公网暴露缺鉴权与 SSRF 防护 sharing/share_service.py
url_validator.py
main.py		 分享 URL 指向 /api/public/share/{token} 直接吐裸 JSON 且不可设有效期或撤回；监听 0.0.0.0 时管理写接口与 /login/open 无鉴权；网址可达性探测未拦截内网 IP（如 127.0.0.1、169.254.169.254）。
P1-1 inner_text() 纯文本抓取丢失代码、表格与公式结构 platforms/generic.py
AnswerCard.tsx		 DOM 采集直接读取 inner_text()，压平了代码块语言标签、Markdown 表格、超链接与多级标题；前端仅用 whitespace-pre-wrap 渲染纯文本。
P1-2 PDF 导出未注册中文字体，中文内容易变方块乱码 export/pdf_exporter.py
html_exporter.py		 xhtml2pdf 默认西文字体不含汉字字形，未映射系统 CJK 字体文件（如 Noto Sans CJK / PingFang / 微软雅黑）。
P1-3 同步 I/O 混入异步事件循环，批量扫描串行耗时极长 llm_synthesizer.py
platform_routes.py
health_checker.py		 scan_accounts 串行探测 23 个站点（单站超时 12s），最坏阻塞数分钟；LLM 最优解采用同步 httpx.Client 非流式整包等待；单次健康检查反复冷启动 Chromium。
P1-4 新建会话未触发各平台开启新对话，旧上下文跨会话污染 default_platforms.yaml 全部 23 个平台的 new_chat_button 均为空，新会话复用已有 Tab 时仍接在旧对话流末尾提问。
P1-5 缺少「网页 CDP + 官方 API」双通道混合调度能力 platforms/base.py 已配置的各大模型 API Key 仅能用于事后合成，不能直接作为高速稳定的问答通道或网页失效时的自动降级兜底。
P2-1 React 平台管理界面缺少增删、排序、导入导出与选择器测试器 platform-manager/*.tsx 后端 CRUD 与导入导出接口已备齐，但前端仅暴露了修改 URL 与 JSON 文本框，未兑现零代码新增平台与可视化选择器在线验证。
P2-2 移动端丢失导出/分享功能，历史会话不支持重命名/删除/搜索 MobileLayout.tsx
SessionHistory.tsx		 ExportMenu 仅存在于桌面侧边栏，手机视图未挂载；历史会话随使用增长后无法检索或清理。
P2-3 WS 断线重连引发重复提问，PWA Service Worker 易缓存旧壳 useWebSocketAsk.ts
service-worker.js		 WS 闪断重连会重发 action="ask" 产生重复问答轮次；静态导航采用永久 cache-first 导致前端升级后不刷新。
P2-4 脚本写死 macOS 路径，CI 缺少前端构建与代码规范门禁 start_chrome_cdp.sh
.github/workflows/ci.yml		 start_chrome_cdp.sh 未适配 Linux Chrome 路径；GitHub CI 未执行 frontend 的 tsc && vite build。

下一步开发优化计划（三阶段版本升级路线图）

v0.3.0 基石加固版：核心稳定性、数据备份与双端体验闭环
优先级：最高 · 清零全部 P0 缺陷

1. 适配器生命周期与无焦点并发锁

将 GenericAdapter.ask() 拆解为 prepare_page / locate_input / fill_question / submit_question / stream_response 标准钩子以激活专用适配器；引入同域名 asyncio.Lock 与 Page 独占租约，移除常规 bring_to_front() 焦点抢占；将 first_token_at 修正至首字符产出时刻，并补齐新会话自动点击 new_chat_button。

2. HTML → Markdown 保真提取与富文本渲染

在 DOM 提取层通过结构化转换脚本保留 <pre><code> 语言标识、表格、列表、链接与数学公式；React 端 AnswerCard 与 OptimalAnswer 接入安全 Markdown 渲染、代码高亮与一键复制代码片段。

3. 数据库自动热备与单事务原子导入

新增 storage/backup.py（基于 sqlite3.Connection.backup），在任何 Schema 迁移、平台全量导入、重置操作前强制生成时间戳热备份并保留轮转快照；重构 import_json_replace 为先全量校验、后单事务原子提交，失败 100% 自动回滚。

4. WS 幂等续传、分享页 UI 与中文字体 PDF

服务端引入 ActiveRunRegistry 支持重连发送 action="subscribe" 幂等续传；新增前端只读分享页与移动端导出/分享抽屉；为 xhtml2pdf 自动注册跨平台 CJK 字体；补齐 Linux start_chrome_cdp.sh 与 CI 前端构建检查。

v0.4.0 混合引擎版：Web CDP + 官方 API 双模调度与可视化平台治理
核心突破：速度跃迁 · 零代码运维

1. Web CDP + API 双通道混合适配器

新增 ApiPlatformAdapter，支持将已配置密钥的模型直接作为高速问答源参与并发，提供 web_only、api_only、web_with_api_fallback（网页失败自动无感切 API）三种运行策略。

2. 全链路异步并发与流式最优解

将 llm_synthesizer 升级为异步流式输出（WebSocket 实时推送 optimal_delta）；url_validator 与 scan_accounts 全面切换 httpx.AsyncClient 并发探测，23 平台全量扫描压缩至 5 秒内。

3. 完整平台工作台与在线 SelectorTester

前端补齐新增/删除平台、拖拽排序、分组过滤、配置包导入导出，并上线「选择器在线实时测试器」——输入选择器即返回匹配元素数量、可见性、文本预览与页面高亮截图。

4. 会话全生命周期管理与全文检索

支持会话重命名、置顶、删除与基于 SQLite FTS5 的跨会话全文搜索；升级 PWA Service Worker 为导航 network-first + 静态指纹资源 cache-first。

v1.0.0 生产旗舰版：安全协同、幻觉交叉核验矩阵与多模态支持
架构升维：高可信决策 · 团队级就绪

1. 远程安全治理、限流与可控分享

非本机回环监听时自动启用访问令牌鉴权；url_validator 增加 DNS 解析后私网/元数据 IP SSRF 阻断；引入 API 令牌桶限流；分享链接支持有效期（24h/7d/30d）、访问计数与随时吊销。

2. 观点分歧矩阵与幻觉交叉核验面板

升级对比引擎为结构化「共识结论 + 事实分歧预警 + 五维评分卡（准确性/深度/结构/代码规范/速度）」，内置科研文献综述、生信分析、代码评审等专业领域合成模板。

3. 多模态图像与文档并发提问

支持上传图片、PDF、DOCX、CSV 及代码文件，API 通道直传多模态载荷，Web CDP 通道通过文件输入控件自动注入附件。

4. SQLite / PostgreSQL 双引擎与可观测看板

引入版本化迁移支持平滑切换 PostgreSQL；提供各平台 7 日成功率、中位 TTFT、P95 延迟与选择器健康度监控仪表盘。
